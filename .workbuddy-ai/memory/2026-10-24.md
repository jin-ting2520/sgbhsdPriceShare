# 2026-10-24

## 修复：管理后台登录后报"缺少请求签名（X-Timestamp / X-Nonce / X-Sign）"

**根因**：服务端验签（server/sign.js checkAdminSignature，40113）正常，全部 68 项测试通过；报错说明浏览器执行的 admin 前端包未携带签名头——即浏览器跑的是升级前的旧 bundle（`/bundle/admin.js` 由 public/dist 提供，旧包在验签特性提交前构建）。触发条件：服务端已升级但浏览器标签页/SW 缓存仍是旧包，或部署的 dist 产物过期。

**修复**：
1. `scripts/build-ui.js`：isStale() 从 mtime 比较改为源码内容哈希 + `.build-manifest.json`，杜绝拷贝/同步场景下时间戳错导致漏重建。
2. `public/js/admin.js` / `app.js`：40113/40112（验签失败）不再误报"登录已过期"并清 token，改为提示强制刷新（Ctrl+Shift+R）。
3. `public/sw.js`：缓存版本 v8→v9， activate 时清除旧预缓存包。
4. `server/index.js`：/bundle/:name 拒绝点文件（防 manifest 直出）。
5. DEPLOY.md FAQ 补充 40113 条目与升级说明。

**验证**：node --test 全量 68/68 通过；smoke 通过；esbuild 层面确认 X-Timestamp/X-Nonce/X-Sign 进入 bundle；/bundle/admin.js 200、.build-manifest.json 404。

**经验**：本项目前端经 esbuild+obfuscator 构建到 public/dist（gitignore），由 Dockerfile `npm run build:ui --force` 或服务启动时 ensureBuild() 生成；排查"新旧代码不一致"类问题时要同时看服务端版本与浏览器实际执行的 bundle 版本。
